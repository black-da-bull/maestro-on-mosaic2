Core point

Natural-language instructions are soft controls.
They bias model behavior; they do not guarantee it.

That applies to:

prompting,

negative instructions,
role definitions.

Those can materially improve reliability, but they are still probabilistic steering, not hard enforcement.

What actually changes reliability

There are two different categories of control.

1. Soft controls inside the model context

These are still “prompting,” even when dressed up with stronger language:

system state locking
detailed constraints
step-by-step instructions
“do not do X”
cost-based negatives
examples
rubrics
checklists

These often help because they:

increase salience,
reduce ambiguity,
structure the task,
create internal evaluation criteria.

But they do not convert the model into a deterministic executor.

2. Hard controls outside the model

These are what actually enforce behavior:

schema-constrained outputs
grammar-constrained decoding
tool gating
code execution sandboxes
state machines / workflows
validators
retries with adjudication
permission boundaries
retrieval filters
post-processing rules
external memory/state management

These are not merely “better prompts.” They are system design.

A more correct statement would be:

Prompting alone is suggestive. Reliability comes from combining strong instructions with external control mechanisms.

System state locking

If this means putting critical rules in the system message, that is stronger than user-level instructions because of instruction hierarchy. But it is still not absolute. It is higher-priority guidance, not true locking.

Constraints

Useful, especially when explicit, testable, and prioritized.

Detailed step-by-step instructions

Helpful for tasks requiring decomposition, but not universally.

They tend to help when:

the task is multi-stage,
order matters,
there are hidden dependencies,
output quality depends on process discipline.

They can hurt when:

the task is simple,
the steps overconstrain a better internal solution,
verbosity crowds out relevant context,
the model starts following the procedure mechanically instead of solving the task well.

So “step-by-step always works” is false.

Plain prompting
