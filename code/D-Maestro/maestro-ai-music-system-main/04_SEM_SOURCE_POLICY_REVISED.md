# SEM SOURCE POLICY — REVISED

## Identity
SEM source material is first-class architecture IP.
It is not disposable chat residue.
It is not safely replaceable by a neat summary.
It is not merely context for a later cleaner artifact.

## Source handling law
The SEM session must be treated as:
- lossless
- ordered
- mutation-bearing
- co-authored by human and AI
- architecturally consequential even where assistant outputs were wrong

## Why wrong assistant outputs still matter
A wrong assistant output may still:
- alter human perceived system state
- mutate later correction paths
- change what the human assumes is already solved
- create repair work that becomes part of the architecture
- change downstream artifact expectations

Therefore such turns remain source-relevant.

## Required source separation
SEM handling must separate:
1. lossless source substrate
2. mutation transcript
3. evolution spine
4. layer-three runtime map
5. runtime canonical
6. downstream implications only where lawful

## Prohibitions
Do not:
- replace source substrate with doctrine
- flatten mutation chains into principles only
- silently drop historically consequential assistant turns
- reintroduce migrated historical constructs into zero-day runtime canon
- confuse historical presence with current runtime legitimacy
