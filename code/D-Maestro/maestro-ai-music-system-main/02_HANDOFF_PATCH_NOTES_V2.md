# HANDOFF PATCH NOTES — V2 REPLACEMENT SET

## Purpose

This patch replaces earlier handoff-pack documents that were directionally useful but insufficiently faithful to the session’s later evolution.

## Why patching was necessary

Earlier handoff documents had four core defects:

1. **SEM compression defect**
   - SEM was reduced to a runtime doctrine too early.
   - The co-authored, turn-by-turn evolving architecture was not preserved sufficiently.

2. **Artifact-class confusion**
   - Source substrate, mutation replay, runtime canon, and downstream shell law were not separated sharply enough.

3. **Legacy leakage risk**
   - Historical module families such as CREW_TAGS, Road-Map, and standalone FX were not consistently treated as migrated historical state.
   - That made zero-day emission riskier than intended.

4. **Layer-three under-modeling**
   - MOSAIC Plane 3 was described but not fully represented as a runtime subsystem with explicit functions, bindings, and enforcement surfaces.

## What this patch replaces

This patch is intended to replace earlier versions of:
- root prompt
- SEM source handling
- SEM mutation representation
- SEM evolution carry-forward
- SEM layer-three mapping
- SEM runtime canonical
- manifest / replacement guidance

## What is different now

### 1. Root prompt corrected with hindsight
The revised root prompt now:
- treats assistant errors as mutation-bearing evidence when consequential
- requires A -> B -> C mutation reconstruction
- enforces source / runtime / downstream separation
- explicitly blocks legacy leakage into zero-day canon

### 2. SEM reconstructed as a stack, not a file
The replacement set separates:
- SEM source policy
- SEM mutation transcript
- SEM evolution spine
- SEM layer-three runtime map
- SEM runtime canonical

### 3. Legacy migrations formalized
Known migrations are now explicit:
- CREW_TAGS -> Voices
- Road-Map -> Performance execution / map logic + section-header bars
- standalone FX -> Timbre + section headers + lyric-row sfx

### 4. Plane 3 fully modeled
SEM Layer 3 is now represented as:
- address-bound
- worker-accessible
- phase-coupled
- controller-visible
- admissibility-driven
- compression-aware
- output-governing

## Replacement rule

For zero-day / air-gapped use:
- use only the revised documents in this patch pack
- treat earlier versions as superseded where they conflict
- preserve earlier versions only as historical lineage, not active runtime canon
