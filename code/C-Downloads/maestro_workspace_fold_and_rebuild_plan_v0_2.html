00 · Reconstruction contract

State, restated before synthesis

The canon-state is declared up front as a contract, not a vibe-check. v0.2 supersedes v0.1 on one structural point: there are not four co-equal planes. There is one app — Maestro, a compiler — and its expansion onto Mosaic; the dev environments are the ground where it ran, and the recovery work is tooling. (§04.)

The corrected first law

Each session folds its activity into a structured fold. Fold the folds — laminate each onto the prior, every under-layer preserved with provenance, so the structure grows in height through compression. A fold may never flatten away what it folded, nor stand alone in place of the folds before it. Contract to grow.

04 · The correction

One app and its expansion — not four planes

v0.1 drew four co-equal planes — Maestro, Mosaic, the dev environment, and the forensics. That was a category error, and it is retracted here. Those four things do not sit at the same level.

Retracted (v0.1)

Four peers: Maestro · Mosaic · Dev_Environment · Forensics — as if each were an equal region of one system.

Corrected (v0.2)

There is one app: Maestro, a compiler. Mosaic is its substrate — the expansion it mounts onto. The dev environments are the ground it ran on (source & evidence). The recovery work is tooling — a dev feature set, not part of the runtime.

Maestro is a compiler — three stages

Source language, intermediate representation, target. The same shape as a software compiler, with music as the problem domain.

Front end

Decompose the creative seed — expanded, not summarized — into granular fields across the constrained axes. Every field is address + value + condition: a rule, not a datum. A null must be lawfully filled or explicitly defended. Nothing silently dropped or invented.

Optimizer

Simulated specialist workers — fallible by design — apply adversarial pressure. A bounded controller checks each field against admissibility and routes (back on fail, forward on pass); it never authors. Deliberation ends on convergence, with a halt for circular argument. The survivor is locked.

Back end

Factor the locked representation: hoist recurring terms to the smallest covering scope, and emit three artifacts mapping to Suno's three inputs. The factoring rule is the routing rule. The lyrics-prompt artifact is itself a structured container executing inside Suno's prompt field. This is FOIL (§06).

The real four planes: the v.0 diagram's internal architecture

"Four planes" is correct — but they are the internal architecture of the one app, as drawn on the Maestro v.0 featuring the new Mosaic Engine diagram (the formalized rebirth destination, specified-not-built).

The v5 loss, at the structural levelv4.5x executed because the monolithic prompt + knowledge files + blueprint.json operated as one integrated thing. ChatGPT rendered v5 as a distributed file system — splitting that whole into separate files — and the split severed the connective tissue, dropping the importance and detail of the components and, inside them, SEG and FOIL. This is the song.excellence.yaml / v3.0g hollowing one level up: not file-contents emptied, but the linkages between files cut. Hence the shipping law: distribute into files only if every linkage is preserved and provenance-bound (blueprint→UST, Technical↔Creative axis identity, SEG/FOIL internal structure).

05 · The runtime loop

How Maestro actually runs

Maestro is a loop that simulates a record label: it fills a constrained null-structure through staffed deliberation, pressure-tests it to congruency, locks it, then reverse-compiles it into maximal-density Suno prompts. The eight steps below are the loop; they are also the Day 2 eight-phase order, read as execution rather than as a static contract.

  1. Pre-load the Technical UST. A skeleton of pre-existing nulls — 9 axes × 5 keys × 5 subkeys. A null is a reserved address waiting to be filled, not an absence.
  2. Blow up the intake. The creative seed is exploded into note-fields placed in the right axes — lossless, nothing the user said is dropped. Lyrics drop into LYR and lock; the lock doesn't limit, because the creative room lives in every other axis.
  3. Fill forward, sequentially. Employee bots work each axis in order — arrangement (music + vocals) → style + instrumentation → performance + post-production — replacing nulls with {"gold reference"} exemplars and Song Excellence as {"baselines"}. The UST gives them constraint-based unlimited creativity. The employees are deliberately flawed individuals, to push unorthodox choices and train Suno; each shows its reasoning and carries it forward. → a complete draft.technical.ust.
  4. Round-robin staff meeting. Not turns — the target is congruency. The owner of each choice defends it with evidence. High-tier choices cascade down (swap VOC baritone→soprano and the whole sonic wall moves), but affected employees push back and outvote — "call bullshit" — so every aspect is pressure-tested, not dictated.
  5. Executive committee. Once the staff reach congruency, market and historical pressure refine the draft against the "red-pen" guidelines and guardrails.
  6. Loop until pass. A fail goes back to the employees and re-runs. A pass is a locked.technical.ust — the upstream truth object.
  7. Reverse pass + FOIL. Reverse back out through the employees, turning the filled UST into prose across three concurrently-developed, intertwined surfaces, maximizing all three of Suno's input character budgets. FOIL works from the edges — granular control plus dedup, promoting recurrence up so each surface carries maximal unique content (§06).
  8. Generate. Suno as the world's best DAW: any song into any genre. The Creative UST is the meso container — granular control over the generative creation.

06 · FOIL — the recovered middle

The compiler cascade, restored

FOIL is a compiler-grade tiered cascade for the song representation — word-level granular control without prompt bloat, plus deterministic dedup by upward promotion. The promotion contract kept one of its three mechanisms; the full structure is recovered in foil_reconstruction_v0_1.md and summarized here.

The four-tier cascade (configuration inheritance, with upward dedupe)

TierWhat it controlsWhere it livesNotation
MACROGlobals / defaults — true 80–100% of the songthe STYLE PROMPT (canonical MACRO container)—
MICROPer-axis module settings — how the song behaves in generalthe UST axis containers (Theory…Post)macro.key.subkey.variable+1
TACTICALSection staging — "what changes when"; structure + override callssection headers, sFX blocks, roadmap, repeatsstanza.section header
VARIABLE+1Line- and word-level switches (FX, pitch, performer tokens, adlibs)lyric lines, word triggers, per-line macrosline.word

The +1 is the extra control knob bound to a value — priority, trigger, constraint, exception, "only on hook." So Voice.register.lead = male low tenor, and Voice.register.lead +1 = mono_center_priority.

The "math" — a merge stack

Effective instruction at render-time:

MACRO defaults
⊕ MICRO axis settings
⊕ TACTICAL section overrides
⊕ VARIABLE+1 atomic triggers

⊕ = merge; later tiers override earlier ones only where specified. This determinism is what makes promotion well-defined.

Duplicate-promotion up-shift

  • A word-trigger repeating across many lines in one section → promote to the TACTICAL header.
  • A tactical rule repeating across sections → promote to MICRO (axis level).
  • A micro rule repeating across most songs → promote to MACRO (style-prompt global).

Recurrence climbs to the smallest scope that covers it — the memo's "hoist to smallest covering scope." It works from the edges inward.

Sheet-music repeat grammar (compiler-facing)

Internal primitives the compiler understands — RPT, TAG, VAMP, ENDING, DS_AL_CODA — so the chorus isn't retyped four times. Suno renders best with explicit lyrics, so a serializer pass expands the repeats into full section blocks before render: token efficiency in authoring, reliability at render.

Runs at both ends of the loop

Forward: macro.key.subkey.variable+1 is how the nulls are addressed during the fill — FOIL is the addressing grammar. Reverse: after lock, FOIL factors the representation and the scope of a term's recurrence decides which of the three surfaces it lands in. The factoring rule is the routing rule.

The fix the truncation forcesThe axis codes (THY/VOC/STY/TIM/PER/POST/MAP/LYR/VIS) are truncations made for character economy — and they break the Technical↔Creative link (Technical VOC vs Creative [Voices]; MAP vs a removed roadmap block; LYR vs ▸LYRICS BLOCK). The fix is a canonical axis registry binding full name ↔ short code ↔ Creative-UST container label, with codes demoted to aliases over one stable identity. THY=Theory, VOC=Voice, STY=Style, TIM=Timbre, PER=Performance, POST=Post-production, MAP=Roadmap, LYR=Lyrics, VIS=Visual Identity.

09 · Code to review

The hard controls, as code

These are the formalizable pieces — deterministic checks and structures, model-independent. The flow never moves in here. guardrail.py is the load-bearing one: the memo's PoC requires exactly one hard control implemented as code, and this is it. The two new files encode this session's recoveries.

guardrail.pypython · the PoC hard control
# A derived artifact may not drop a source element or revert a
# locked operator value without a logged supersession.
# A code check, not a prompt. Fail-closed. Would have caught both losses.

LOCKED = {"release_threshold": 97.5}   # operator-locked (CR-009)

def check_derived(source: dict, derived: dict, supersessions: set) -> list:
    violations = []
    # (a) no dropped elements
    for key in source:
        if key not in derived and key not in supersessions:
            violations.append(f"DROPPED: {key} in source, absent in derived")
    # (b) no reverted locked values
    for key, locked_val in LOCKED.items():
        if key in derived and derived[key] != locked_val \
           and key not in supersessions:
            violations.append(
                f"REVERTED: {key}={derived[key]!r} overrides {locked_val!r}")
    return violations   # empty == PASS
foil_merge.pypython · recovered FOIL math
# effective = MACRO ⊕ MICRO ⊕ TACTICAL ⊕ VARIABLE+1
# later tiers override earlier ones ONLY where specified.
TIERS = ["macro", "micro", "tactical", "variable_plus_1"]

def resolve(field_addr: str, layers: dict) -> dict:
    # merge the four tiers for one address; later wins where present
    effective = {}
    for tier in TIERS:                       # MACRO first, VARIABLE+1 last
        spec = layers.get(tier, {}).get(field_addr)
        if spec is not None:
            effective.update(spec)           # override only specified keys
    return effective

def upshift(rec: dict) -> dict:
    # promote a recurring term to the smallest scope that covers it
    if rec["songs_spanned"] > 1:    return {"promote_to": "macro"}     # across songs
    if rec["sections_spanned"] > 1: return {"promote_to": "micro"}     # across sections
    return {"promote_to": "tactical"}                                  # within one section

# one stable identity per axis; code is an alias; creative label bound.
REGISTRY = {
  "Theory":          {"code": "THY",  "creative": "[Theory]"},
  "Voice":           {"code": "VOC",  "creative": "[Voices]"},
  "Style":           {"code": "STY",  "creative": "[Style]"},
  "Timbre":          {"code": "TIM",  "creative": "[Timbre]"},
  "Performance":     {"code": "PER",  "creative": "[Performance]"},
  "Post-production": {"code": "POST", "creative": "[Post-Production]"},
  "Roadmap":         {"code": "MAP",  "creative": "[Roadmap]"},   # restored
  "Lyrics":          {"code": "LYR",  "creative": "LYRICS BLOCK"},
  "Visual Identity": {"code": "VIS",  "creative": "[Visual]"},    # 9th axis
}
_BY_CODE = {v["code"]: k for k, v in REGISTRY.items()}

def link(code_or_name: str) -> dict:
    # resolve any code OR name to the one canonical identity + labels
    name = code_or_name if code_or_name in REGISTRY else _BY_CODE.get(code_or_name)
    if name is None:
        raise KeyError(f"unknown axis: {code_or_name!r}")   # fail-closed
    return {"canonical": name, **REGISTRY[name]}
mutation.pypython · mutations, not turns
# each turn becomes an addressable state-transition with provenance.
from dataclasses import dataclass, field

@dataclass
class Mutation:
    input_claim: str                 # what the turn asserted
    prior_state_changed: str         # what it altered
    contradiction_resolved: str      # which conflict it closed
    new_nodes: list = field(default_factory=list)
    new_edges: list = field(default_factory=list)
    authority: str = "PROPOSAL"      # ROOT (human) | PROPOSAL (ai)
    downstream_effect: str = ""
    source: str = ""                 # provenance anchor

def fold(state: dict, m: Mutation) -> dict:
    # append-only: corrections win retroactively; never rewrite the past
    if m.authority == "ROOT":
        state = apply_root(state, m)
    state.setdefault("ledger", []).append(m)   # keep the ugly parts
    return state
