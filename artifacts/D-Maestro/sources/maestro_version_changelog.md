## Lineage A — Dynamic Living Document (v1.0 → v2.1)

The early scaffolding phase. The goal stated repeatedly by the user is a single,
auditable, fully self-contained "living document" that never drops detail
through summarization, truncation, or "(unchanged)" placeholders.

### v1.0 — Initial Draft *(EX01)*
First artifact. Built directly from the pasted research dump on recursively
structured, multi-agent AI musicology. Establishes the core concept: a
collaborative AI "band" of specialized agents.

### v1.1 — Creative OS Workflow *(EX06)*
**Trigger:** the user's "WE ARE RESTARTING" instruction — banning summarization,
truncation, and placeholder text; requiring the process to be auditable,
peer-reviewable, and fully self-executing. Adds the Creative OS workflow layer.

### v1.2 — Sonic Orchestrator + System Personas *(EX07)*
**Trigger:** "continue writing." Expands the document with the Sonic
Orchestrator workflow and the first defined system personas.

### v1.3 — DeepSearch Research Persona *(EX08)*
**Trigger:** `/deepdive`. Integrates the DeepSearch AI Research Assistant
persona for deep-reading authoritative sources.

### v2.0 — Full Session Synthesis *(EX09)*
**Trigger:** the user pastes a full external chat transcript and asks for it to
be parsed into individual exchanges and integrated. Major bump: the document
becomes a synthesis of an entire prior session.

### v2.1 — Integration Scaffolding for the Creative OS *(EX12)*
**Trigger:** the user flags that the assistant has slipped into Q&A mode instead
of iterative-development mode, and references 10 attached documents. Reframes the
document as scaffolding for the forthcoming operating system.

## How to Read the Numbering

- **Major** — new conceptual generation: `1.x` (Dynamic Living Document) →
  `2.x` (session synthesis) → `3.0` (first OS) → `4.x` (Composer-Class OS).
- **Minor** — a new capability or structural layer: `4.2 → 4.3 → 4.4 → 4.5`.
- **Micro** — a persona, constraint, or subroutine added to an existing
  structure: `4.3.0 → 4.3.1 → 4.3.2`, `4.4.0 → 4.4.1`, `4.5.0 → 4.5.1 → 4.5.2`.
- The `v3.0 → v4.2.3` gap and the in-place EX28 update are the two points where
  the declared numbers do not follow this pattern cleanly.
