## 3. Lineage reconstruction by stage
### Stage A — proto-framework / session-player era
**Center of gravity:** song prompting, section logic, style/timbre/performance containers, and session-player metaphors.

**Key signals:**
- creative prompting and song-building are structured around section tags, narrative style, instrumentation logic, and iterative AI-human collaboration.
- the “studio/session” metaphor already exists: UST is not a loose tag cloud but a more disciplined creative structure.

**What remains invariant later:**
- UST is not merely a vibe list
- structured sections matter
- musical work is treated as collaborative labor rather than isolated inspiration

### Stage B — master-spec / compiler-spine era
**Center of gravity:** the system becomes an audio-native creative–technical operating system and compiler pipeline.

**Recovered stable elements:**
- UST becomes the primary technical specification object and single source of truth.
- eight mandatory axes are formalized.
- councils, SEG, G-Card, song decks, migration law, and failure-mode prevention are explicit.
- the end-to-end M-pipeline runs intake → fragment analysis → UST drafting/refinement → enforcement → validation → prompt compression → generation → migration.

**Architectural identity:** still controller/compile-centric, but already more than a simple prompt framework.

### Stage C — v4.2.3 OS / QA harness consolidation
**Center of gravity:** stricter tooling, validators, HPA metrics, E2E harnesses, persona-as-plugin grammar, and analysis overlays.

**Key additions:**
- validators, HPA metrics, A→T→A cycles, E2E harness, round-robin, feedback learning, and output contracts.
- stronger auditability and repeatability.

**Meaningful delta:** quality governance becomes more explicit and operational, but runtime identity is still closer to governed pipeline than staffed organization.

### Stage D — Chimera / Indigo / quality-governance expansion
**Center of gravity:** deeper governance, forensic postmortems, upgrade ledgers, strict container rules, lyric quality baselines, anti-corny firewalls, trauma-aware evidence handling, and command/routing behaviors.

**Key deltas:**
- Excellence Gating is recognized as under-specified and must become a true QA pipeline.
- conversation analysis and postmortem engines become part of system learning.
- UST is increasingly described as studio / call sheet / rehearsal environment rather than prompt.

**Branch note:** this branch contributes strong governance and quality discipline but is not yet the final Maestro v5-c ontology.

### Stage E — persona recovery and staffing turn (`Yesterday.txt`)
**Center of gravity:** missing persona layer becomes a forcing function; Maestro starts being reconstructed as a staffed organization.

**Core chapter sequence:**
1. blocked persona doc → absence assessed as system failure surface
2. Mo evaluated as high-fidelity but operationally incomplete
3. second blockage → reconstruct from first principles becomes lawful path
4. Canon appears → structure/governance separated from feel
5. Metro appears → feel/culture become first-class authority
6. Mo/Canon/Metro triad forms
7–14. specialist roles are added one by one (Alan, Dave, Melody Scout, Megazord, Vanessa, Sage, Anva, Eldrik, Analog Confessor, Sibling Architect)
15. staff recognized as a virtual label
16–18. orchestration and single-invocation options appear
19–21. decisive late corrections: Technical UST = middleware; Creative UST = derivative; null-filling by argumentative SME reasoning = true engine

**Major branch point:** the architecture stops being “one smart orchestrator with helpers” and becomes “worker-owned semantic labor over a canonical substrate.”

### Stage F — Day 2 bridge formalization
**Center of gravity:** migration safety, anti-drift hardening, controller lockout, artifact ontology, freeze taxonomy, exact phase order.

**Key deltas:**

## 4. Deduplicated delta map
### 4.1 Naming / taxonomy deltas
- **UST** stays stable as the technical substrate, but its meaning sharpens from “technical song blueprint” to “dense canonical middleware / governed constraint kernel.”
- **Creative UST** moves from sometimes being treated as parallel output to clearly being a lossy downstream derivative.
- **Show Summary** stabilizes as derivative style surface.
- **Persona** evolves from descriptive/tonal profile to bounded worker / virtual employee.
- **Councils** recede as the primary identity model; worker/staff/runtime language becomes dominant.

### 4.2 Document-structure deltas
- early monoliths organize around master-spec sections and pipeline stages.
- later bridge artifacts organize around contracts, artifacts, readiness, freeze states, and ontology distinctions.
- final v5-c runtime material organizes around world model, workforce, pressure, and bounded external API.

### 4.3 Workflow-design deltas
- from M-pipeline / compiler stages
- to governance-rich iterative loops

### 4.4 Guardrail / constraint deltas
- Lyrics-Lock and structural validation appear early.
- excellence / QA / non-regression / prosody / anti-corny behavior are hardened later.
- anti-drift broadens into anti-controller-overreach, anti-step-loss, anti-premature-compression, and anti-boundary-collapse law.

### 4.5 Persona / orchestration deltas
- councils / plugin grammar / expert roles

### 4.6 Execution-logic deltas

### 4.7 Project vs workspace boundary deltas

### 4.8 Bridge vs runtime identity deltas

- runtime identity is therefore higher-order than bridge identity, while still constrained by bridge law during migration

## 5. Reversals and branch points

### 5.2 Reversal: personas as flavor/helpful overlays → personas as workers with bounded authority
This is a structural identity shift, not a minor wording change.

### 5.3 Reversal: pipeline/artifact-centric interpretation → addressable null-resolution as true engine
The late null-resolution correction reinterprets much of the earlier machinery.

### 5.4 Branch: Day 2 formalization as productive but dangerous over-center
The bridge stack is necessary for migration safety, but Day 3 critique explicitly warns against letting it define finished-state v5-c.

### 5.5 Branch: modular-formalization council proposals
These are useful for formalization, but they are not identical with the resident creative workforce and should not silently replace it.
