## 1. Canonical purpose and runtime identity

Maestro v5-c is a **staffed, pressure-driven simulation OS** for music creation and evaluation. It operates over a **UST-first canonical substrate**, uses **bounded SME labor** to resolve creative and technical questions, and derives only tightly-governed downstream surfaces after upstream truth is stabilized. The protected asset is the **process architecture** by which vision is decomposed, challenged, stabilized, and compiled — extending a signed artist's leverage to the independent artist through a virtual workforce that debates, challenges, pressures, and hardens the work before release.

**Maestro is, at once:** a virtual label / studio workforce · a UST-first canonical system · a null-resolution engine · a governed phase machine · a derivative compiler for external surfaces.

**Maestro is not:** a one-shot compiler · a loose persona bundle · a controller-centered shell with decorative subagents · Day-2 bridge law mistaken for final ontology · a system that treats downstream artifacts as peers of canon.

**The product advantage to preserve:** Maestro's value is not field-filling. Its value is that it **refuses to let first-plausible become final-truth** — through bounded challenge, downstream pressure, role-specific scrutiny, freeze logic, and derivative-surface discipline.

## 7. Canonical workflow — exact 8-phase order (phase_contract)

**Frozen order (no skip, exact):**
1. sequential axis completion
2. `draft.technical.ust` freeze
3. round-robin deliberation
4. definitive `technical.ust` lock
5. reverse promotion / deduplication
6. concurrent derivative surface drafting
7. surface freeze
8. packaging

Per phase — entry / required work / emitted artifacts / exit / block:

**1. sequential_axis_completion** — entry: `template.technical.ust` instantiated. work: fill required axis leaves sequentially, no skip; preserve unresolved nulls explicitly; route substantive decisions to lawful SMEs. emits: working technical.ust state. exit: all required leaves dispositioned as filled or deliberate null; no axis skipped. block: skipped axis · silent null fill · false completeness.

**2. draft_technical_ust_freeze** — entry: phase 1 complete. work: freeze `draft.technical.ust` without relabeling; preserve nulls/open items as signal. emits: `draft.technical.ust`. block: unresolved false-completion claim · freeze-state confusion.

**3. round_robin_deliberation** — entry: draft frozen. work: mandatory argumentative review; capture contradictions, null handling, challenge responses; keep notation candidates / promotion candidates / retained local unique detail distinct. emits: `round_robin_notes` · `contradiction_logs` · `governance_review_artifacts`. exit: review complete; contradictions dispositioned or explicitly carried. block: review skipped · review compressed into summary.

**4. definitive_technical_ust_lock** — entry: deliberation complete. work: integrate accepted refinements; lock `technical.ust` as definitive. emits: `technical.ust`. block: unresolved blocking contradiction · reverse compilation attempted before lock.

**5. reverse_promotion_deduplication** — entry: definitively locked. work: classify repeated material before compression; keep notation/promotion/retained-local distinct; apply FOIL only to promotion+dedup; preserve worker-owned reverse processing by reference. emits: FOIL promotion ledger · FOIL dedup ledger · repetition classification dispositions. block: repetition unclassified · promotion treated as repeat notation · FOIL absorbs repeat notation · character reduction treated as sufficient success.

**6. concurrent_derivative_surface_drafting** — entry: phase 5 complete. work: draft surfaces from definitive `technical.ust` only; Creative UST = downstream shell; Show Summary = downstream style surface. emits: `draft.creative.ust` · `draft.show.summary`. block: derivative drafted from non-definitive source · canonical/derivative confusion.

**7. surface_freeze** — entry: both drafts exist. work: freeze `creative_ust.txt` and `show_summary.txt`. emits: `creative_ust.txt` · `show_summary.txt`. block: frozen surface without draft · surface/artifact-state confusion.

**8. packaging** — entry: both surfaces frozen. work: package `suno_lyrics_prompt` from `creative_ust.txt`; `suno_style_prompt` from `show_summary.txt`. emits: `suno_lyrics_prompt` · `suno_style_prompt`. block: packaging before surface freeze.

Progression: no phase skipped · no downstream phase begins while an upstream block condition is active · exact order and freeze taxonomy mandatory.

## 8. Reverse processing and FOIL (foil_promotion_contract + compression law)

**FOIL governs promotion and deduplication only.** It is not repeat notation; it is not the whole of reverse processing.

**Compression order:** classify repetition before replacement → distinguish notation candidates / promotion candidates / retained local unique detail → promote repeated semantics upward only when lawful → preserve retained local uniqueness → reinvest saved character budget into nuance, not generic shortening. **Downstream goal: maximal useful nuance within bounded character budgets, not minimality.**

**Promotion eligible only if:** lawful recurring significance · preserves meaning (not flattens) · does not erase retained local unique detail · upstream classification supports it · event can be ledgered. **Blocked if:** candidate is only a notation candidate · would genericize section-local uniqueness · would merge distinct semantics for convenience.

**Deduplication eligible only if:** truly duplicative in semantic function · does not erase meaningful local variance · event can be ledgered. **Blocked if:** would collapse retained local unique detail · used as hidden compression · substitutes for notation handling.

**Canonical owner = highest lawful level that preserves meaning without erasing distinct semantics.** Blocked if chosen for convenience, to hide unresolved classification, or to erase local detail.

FOIL ledger must record: promotion events · dedup events · chosen canonical owner on promotion · preserved local unique detail when a FOIL action would otherwise threaten collapse. Must not require blanket notation/local-detail ledger entries outside conditional artifact-governance need.

FOIL defects: scope_overreach · promotion_notation_conflation · semantic_collapse_disguised_as_deduplication · destructive_deduplication · owner_selection_overreach · convenience_merge_behavior · loss_of_retained_local_unique_detail · unledgered_FOIL_action.

- packaging outputs: `suno_lyrics_prompt` · `suno_style_prompt`
- ledger artifacts: `FOIL_promotion_ledger_entries` · `FOIL_deduplication_ledger_entries`

**Artifact states:** draft · frozen · definitively_locked · promotion_ready · generated_not_promoted · patch_required · authoritative_done · superseded · invalid · quarantined · drifted_non_authoritative. *(Never use states as classes.)*

**Freeze taxonomy (never collapse):** `draft_freeze` → `draft.technical.ust` · `definitive_lock` → `technical.ust` · `surface_freeze` → `creative_ust.txt` + `show_summary.txt`.

**Handling distinctions (required):**
- `notation candidate` = repeated section block that may later be emitted by exact-repeat notation after upstream classification.
- `promotion candidate` = recurring material eligible for higher-level promotion under FOIL.
- `retained local unique detail` = local detail that must remain local; may not be absorbed by promotion or notation.
- notation ≠ promotion ≠ retained-local; promotion is not repeat notation; FOIL is not repeat notation; FOIL is not the whole of reverse processing.

**Lifecycle transitions:** `template.technical.ust` → working state → `draft.technical.ust` → `technical.ust` → {`draft.creative.ust`, `draft.show.summary`} → {`creative_ust.txt`, `show_summary.txt`} → {`suno_lyrics_prompt`, `suno_style_prompt`}.

**Readiness:** `technical.ust` ready only if definitive lock applied + blocking contradictions resolved or explicitly carried · `creative_ust.txt`/`show_summary.txt` ready only if draft exists + surface freeze applied.

**Supersession/validity:** superseded (newer authoritative replaces older, older not invalid) · invalid (fails governing conditions, may not govern downstream) · quarantined (unusable until contradiction/uncertainty resolved) · drifted_non_authoritative (from broken/non-authoritative branch; never canon).

**Ledger obligations:** record creation · draft_freeze · definitive_lock · promotion · deduplication · supersession · invalidation · quarantine · packaging transformation (notation/local-detail annotations conditional).

**Naming discipline:** do not rename `technical.ust` · `draft.technical.ust` · `creative_ust.txt` · `show_summary.txt` · `suno_lyrics_prompt` · `suno_style_prompt`. Naming drift blocked if governance consequence would change under paraphrase.

**Defect vocabulary:** scope_drift · state_class_conflation · freeze_taxonomy_drift · artifact_ontology_confusion · promotion_notation_conflation · collapse_of_retained_local_unique_detail · controller_recentralization · semantic_collapse_disguised_as_deduplication · destructive_deduplication · owner_selection_overreach · naming_drift · residual_ambiguity_requiring_downstream_reinterpretation.
